# Read and run the Python workflow

## Main path: three notebooks

1. **01_data_preparation_and_screening.ipynb:** JSON files → season tables → 79 candidates → event rates → percentiles → scenario scores → shortlist. No database connection is required.
2. **02_sql_staging_import.ipynb:** prepared tables → five SQL staging tables. Used only for a fresh database; the explicit load flag defaults to False.
3. **03_sql_result_validation.ipynb:** compare SQL analytical views with the Python reference after running SQL scripts 03–10.

Each notebook starts in a new kernel and declares its inputs. Notebook 01 saves `data/processed/core_analysis.pkl`; the next two notebooks load this named checkpoint instead of relying on a previous notebook's variables. This local pickle is generated by your own analysis; do not load pickle files from an untrusted source.

Every substantive code cell from `ggg.ipynb` is mapped in [cell_mapping.csv](cell_mapping.csv). The original `%pip install pyodbc` cell is represented by `requirements.txt`. The untouched original notebook is retained in `archive/ggg_original.ipynb`, which is excluded from Git by default.

## Exploration: optional learning material

- `exploration/01_source_selection.ipynb` preserves the early alternative-provider comparison. It explains the source-selection decision and is not required for the final pipeline.
- `exploration/02_impect_data_walkthrough.ipynb` explains the IMPECT structures on one match. It can be read before the main notebook, but the main notebook does not depend on its kernel.

## Advanced metrics: optional extension

The `extensions/` notebooks separate computation, database loading and database validation. These metrics support additional exploration; they are not terms in the published balanced/passing/carrying scores.

1. `01_advanced_kpi_analysis.ipynb` reads the six provider metrics, audits missingness, checks 17 event-KPI exports, records provenance and saves `advanced_analysis.pkl`.
2. `02_advanced_kpi_import.ipynb` loads the payload after SQL 11. Its write flag defaults to False.
3. `03_advanced_kpi_validation.ipynb` compares Python and SQL after SQL 12–13.

There are no cross-notebook `%run` chains or instructions to retain an old kernel.

## Shared Python modules

| Module | Responsibility |
|---|---|
| `config.py` | Fixed season ID, paths, SQL server and database settings. |
| `data_access.py` | Atomic JSON download/cache and explicit season metadata bootstrap. |
| `checkpoints.py` | Save/load only named intermediate objects. |
| `database.py` | ODBC connection construction and explicit load guard. |

The analytical formulas stay visible in notebooks for learning. They have not been hidden behind a large class hierarchy or copied into a second analytical implementation.

## When something stops

- **Checkpoint missing:** run main notebook 01 first.
- **SQL table already contains data:** the duplicate-load guard is working. Use the validation notebook for an existing database.
- **ODBC driver missing:** install Microsoft ODBC Driver 17 or 18 and use the same Windows Python environment as your SQL setup.
- **Cached JSON is invalid:** inspect that file. Move only the confirmed damaged cache file aside and rerun its download; do not replace missing KPI values with zero.
- **Snapshot counts differ:** investigate source changes rather than editing expected counts just to make checks pass.
